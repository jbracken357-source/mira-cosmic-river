# Mira 全范围打磨：光河、观看体验与仪式时刻

状态：2026-09-17 讨论收敛后的发布候选稿；等待整体理解与拆票确认。包含 A+B+C 和正式静帧保存。本次交付规划，不实施产品代码。

## Problem Statement

观看者希望反复进入一个美、浪漫、具有震撼尺度的双星世界，感受到彼此牵引、共同前行。当前已经能探索真实三维场景，具有双星表面、尾巴、直达模式和真实时间绑定，但光河的受光与厚度不够，双星质感不统一，镜头与控制权交接、界面可读性、加载与故障体验尚未完成打磨，也缺少声音和保存一次观看的能力。

## Solution

延续既有穿行体积方向和实时 3D 主场景，使光河拥有前中后景、受光与暗部层次，双星、来流与吸积弧使用一致的美术语言。保留自由探索与每天直达，用精炼界面和可即时打断的镜头提供稳定控制，以自主开启的环境音和可保存的今晚静帧补全仪式时刻。

桌面画面质量优先，接近 60fps 是优化目标；iPhone 14 Pro Max 要求能进入并完成基础观看、交互、声音与保存，不设置手机帧率或高画质完成门槛。

## User Stories

1. 作为观看者，我希望打开即看到有厚度和方向的光河，以便立刻进入这个世界。
2. 作为观看者，我希望近景雾、中景来流和远处双星有尺度差异，以便感受尾巴穿过身边。
3. 作为观看者，我希望拖动时看到真实视差，以便确认探索的是空间而非整体移动的图片。
4. 作为观看者，我希望自由旋转和缩放仍然可用，以便自行寻找喜欢的角度。
5. 作为观看者，我希望不同视角没有明显薄片、矩形边缘、重复亮圈或接缝，以便保持沉浸。
6. 作为观看者，我希望巨星、白矮星和吸积弧具有一致质感，以便相信它们属于同一世界。
7. 作为观看者，我希望两星之间的物质流随相伴运动保持连接，以便看见牵引关系。
8. 作为观看者，我希望亮处仍有细节、暗处仍有结构，以便同时感受温度、深度和柔软气流。
9. 作为观看者，我希望第一次完整开场逐步揭示双星与尾巴尺度，以便获得仪式感。
10. 作为观看者，我希望回访直接进入天空，并可随时重播，以便不被重复开场阻碍。
11. 作为观看者，我希望小字和控件清楚易用但不抢画面，以便自然发现需要的操作。
12. 作为观看者，我希望中文和英文各自排版完整、控件语言一致，以便切换语言后仍可理解。
13. 作为观看者，我希望用键盘打开信息卡、关闭并回到原焦点，以便不依赖精确点击星体。
14. 作为观看者，我希望手机上双星没有被裁出，控件容易点到，以便偶尔用手机观看。
15. 作为观看者，我希望主动操作立即打断自动运镜和结语，以便始终掌握视角。
16. 作为观看者，我希望闲置后天空恢复缓慢运镜，以便放手观看仍有变化。
17. 作为观看者，我希望读卡和保存期间镜头不擅自接管，以便完成当前动作。
18. 作为观看者，我希望能够回到精心安排的主视角，以便探索后方便恢复构图。
19. 作为观看者，我希望暂停自主运动或使用系统减少动态效果偏好，以便舒适观看。
20. 作为观看者，我希望默认静音、主动开启全程环境音，以便自行决定观看氛围。
21. 作为观看者，我希望声音偏好被记住，且失败时不显示虚假的播放状态，以便信任控制反馈。
22. 作为观看者，我希望重播不会叠加音轨，后台不会继续打扰，以便安心切换任务。
23. 作为观看者，我希望保存按下按钮那一刻的当前视角，以便留下今晚的 Mira。
24. 作为观看者，我希望保存的图片没有操作界面，可选择日期和固定短句，以便留下干净画面。
25. 作为观看者，我希望保存失败可以重试、手机也能取得图片，以便实际使用而不只是看到成功提示。
26. 作为观看者，我希望今晚与其他日期在亮度、局部色温和微妙细节上不同，以便愿意回来观看。
27. 作为观看者，我希望加载慢或素材失败时仍有有意义的画面，以便不陷入空黑等待。
28. 作为观看者，我希望三维绘制失效时看到静态后备与重试，以便知道如何继续。
29. 作为观看者，我希望电脑尽量展示好的效果并避免持续卡顿，以便长时间观看。
30. 作为观看者，我希望换到后台再回来时不突然跳镜头、不补播积压动作，以便保持观看连续性。

## Implementation Decisions

### 视觉与素材

- 沿用 React、TypeScript、Vite、R3F/Three.js、Zustand、Motion 和 Tailwind。连续场景更新留在渲染循环；界面订阅离散阶段，避免开场时间造成不必要的逐帧 React 更新。
- 以既有去塑料感目标作为质感参考，保留蓝紫、珍珠金、暖星体和柔软薄雾。明确近景雾、中景主体、稀疏细亮丝与远景职责，先校准色彩输出链路、密度权重和受光，再决定是否需要新局部素材。
- 显式让星体位置与密度结构影响光河受光；不把点光源对象存在视为自定义 shader 已受光，也不靠全局 bloom 掩盖问题。
- 素材仅提供局部密度/细节，空间、颜色、运动与遮挡由实时场景负责。缺图保留程序化回退，来源/授权、用途和处理记录可追溯。
- 新素材、GPU 粒子模拟或局部体积绘制是有证据才采用的手段，不是交付数量指标。不为视觉升级增加第二套常驻渲染引擎，不用锁相机规避穿帮。
- 白矮星核心保留层次，吸积流呈柔软、断续且明暗不均的弧，避免白珠与完整硬圆环；巨星减少满表面同强度高频纹理，来流的宽度和亮度连续连接到局部热斑。
- 完整开场保留约 15 秒，镜头通过节奏、尺度与视差展开尾巴；回访保持直达，不强制等待开场。

### 界面与观看控制

- 中文/英文标题、正文、结语均定义实际可用的字体与回退；控制文字清楚可读，视觉上克制，交互目标约 44px；不新增完整设置面板。
- 信息卡补可访问名称、滑杆标签、Escape、焦点恢复与可键盘到达的星体入口。桌面信息卡按非模态说明处理，不无故锁住场景焦点；移动端保持能读能关闭。
- 信息卡进入约 180–240ms、退出约 120–180ms；减少动态效果使用即时变化或简短淡变，不采用滑入。慢节奏用于镜头而非等待操作反馈。
- 首次自主运镜、主动探索、闲置恢复、结语、读卡、保存、完整开场、暂停和后台状态必须有唯一清楚的控制权规则。
- 最后一次有意操作后 30 秒闲置才恢复自动运镜，用约 3 秒渐进恢复运动，避免瞬间跳回预设；60 秒闲置后允许结语镜头与文字。读卡、保存、手动暂停、后台和减少动态效果期间不触发闲置接管。
- 30 秒和 60 秒均从同一次最后有意输入计时，自主运镜不视为观看者活动；读卡和保存期间不积累可接管闲置，结束从零计时。
- 拖动、滚轮、触摸或按键立即打断自动运镜/结语；不等轮询。关闭信息卡、保存结束或恢复前台后重新计算闲置，不立即触发积压结语。
- 回到主视角和重播是明确主动动作；减少动态效果下用即时定位或淡变，避免强制飞行。关闭自主运动后仍允许主动拖动。
- 手动暂停覆盖镜头、轨道和装饰运动，真实时间保持原来源；返回前台不解除手动暂停，主动恢复后重新计算闲置且不补播运动。恢复按钮不能绕过系统减少动态效果偏好；暂停画面不隐式改变声音偏好。
- 提示在第一次成功操作后退场，但键盘/帮助路径可重新发现必要操作。

### 环境音

- 替代旧总 Spec 的纯视觉音频排除：默认静音，主动开启后完整开场和自由观看均可有无歌词、无旁白的轻量环境音，随观看距离作克制变化。
- 记住偏好不等于获得浏览器播放许可；被拒绝时呈现可恢复入口，静音或失败不阻断视觉。重复开关/重播不会创建叠加音轨。
- 进入后台淡出或暂停，回前台保留意愿并尊重播放许可；明确关闭者不自动恢复。优先使用有明确使用权的素材或原创合成，不默认新增付费服务。

### 今晚的 Mira

- 正式交付当前视角静帧保存：按下保存动作时锁定视角、日期、语言和场景相位，保持当前横竖比例，PNG 长边最高 2560px；不带控件，不改变观看构图。
- 默认纯画面；日期和固定短句为可选项，文字随当前语言，日期取保存瞬间本地日期。短句沿用相伴主题，不接受自由输入。
- 点击保存入口立即锁定一次快照，随后预览/选项只改变叠字，不重新取景；失败重试同一次快照，关闭后再次打开才取得新快照。预览是当前保存动作的一部分，不形成完整设置面板。
- 导出有明确进行中/成功/失败状态，连续点击不会堆积任务；保存失败可重试且不丢失观看状态。手机采用浏览器可用的图片预览/保存路径，以实际获得文件为准。
- 不永久启用昂贵的绘制设置或提高常驻分辨率；一次导出临时资源可释放。WebGL 失效时不把静态后备冒充当前实时画面，明确提示先重试场景。

### 真实时间、加载与运行

- 保持单一真实时间来源和确定性周期近似；亮度、局部色温与微小密度变化共同使用该状态，不声称实时观测轨道或收到实时观测数据。
- 主素材就绪或有意义的程序化回退就绪，并出现首个可呈现画面后才开始完整开场。可失败素材不能导致无限等待。
- 三维不可用、context lost、context restored 有静态后备、重试与恢复路径；恢复后交互、声音和状态不重复注册。
- 测量冷启动和解析后再拆分加载；分包本身不作为变快证据。优先尽早展示轻量界面或场景静帧，再进入实时场景，回访无需额外仪式。
- 质量从合理初档开始，根据持续帧率和恢复区间调整，带冷却/滞回避免振荡；优先降低高成本后处理/分辨率，再减少装饰层，保护双星关系和光河方向。
- 后台与完全静止模式管理绘制生命周期，返回时不补播积压运动；普通动态观看仍持续更新。减少动态效果覆盖背景闪烁等遗漏。
- 桌面实际记录设备、GPU、浏览器、分辨率、档位、DPR 与帧时间；接近 60fps 为目标，观看效果优先，不把所有设备固定 60fps 写成承诺。手机无性能硬门槛。

## Testing Decisions

- 延续现有 Playwright 浏览器 E2E，优先从页面输入和可见结果验证：进入、重播、读卡、语言、触控、镜头接管/打断、声音偏好与受阻恢复、静帧保存、失败重试。
- 延续现有星空时钟与质量判定纯函数测试，仅对时间阈值、滞回与状态优先级等有独立业务意义的规则补测试，不镜像组件实现。
- 在确定日期、随机种子、相机和动画相位下保存视觉基准；默认、近景、至少三个旋转视角和竖屏对照。字幕/结语/卡片分别检查遮挡与排版。
- 测试保存文件可解码、尺寸/比例正确、非空且不含控件，取保存动作时刻而非晚一帧更新后的状态。真实设备验证手机取得文件的路径。
- 人为注入慢网、贴图失败、音源失败、播放拒绝、WebGL 不可用与 context lost/restored，验证可理解的反馈和可恢复行为。缺图测试必须检查画面确有内容，而非仅存在 canvas。
- 低质量软件渲染用于行为回归，不作为高档画质或设备性能证明。桌面真实 GPU 做静置约 2 分钟、连续拖动约 30 秒、连续观看至少 5 分钟，记录卡顿、质量切换、资源增长与后台恢复。
- iPhone 14 Pro Max 验证进入、基本拖动/缩放、读卡/关闭、声音开关、保存、横竖屏和安全区域；不设置帧率或发热硬验收目标。
- 使用已有 build/lint/CI 作为工程门槛；观看者确认美术才算视觉完成。未能取得的真机/美术证据明确待验收，不由自动化模拟代签。

## Out of Scope

- 产品代码实施和部署不在本次规划会话内；由后续执行票推进。
- 不换主技术栈，不强制采用 WebGPU、全场景体积模拟或 GPGPU，不叠加第二个背景渲染引擎。
- 不增加账户、云端存储、分享社区、自由文字编辑、任意导出构图/视频或任务游戏系统。
- 不接实时天文服务，不声称当晚精确观测位置；声音不含旁白和歌曲。
- 不恢复手机约 30fps 的旧硬验收要求，也不以手机最低性能压低桌面视觉上限。
- 不重开或改写旧已关闭票，不把旧完成状态等同于新目标验收完成。

## Further Notes

- 本 Spec 延续既有浪漫混合视觉决策，并明确替代旧音频排除与手机帧率硬要求。新的静帧保存已从探索项变为正式范围。
- 本地已有部分光河、双星、镜头与分档实现；任务从当前基线深化，避免重复建设。
- 任务按完整体验纵向拆分，只有真正阻塞交付的依赖才连边。独立功能在当前场景即可实现和验证，最终在新视觉场景统一回归。
- 整体定稿后发布为新总 Spec；父子票和 blocking 关系可追溯。工程票使用 ready-for-agent；最终观看者验收单独标记人工责任，不由 CI 自动关闭。
